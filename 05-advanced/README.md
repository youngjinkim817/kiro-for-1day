# 에이전트 훅

## 에이전트 훅이란?
에이전트 훅은 IDE에서 특정 이벤트가 발생할 때 미리 정의된 에이전트 작업을 자동으로 실행하여 개발 워크플로우를 간소화하는 강력한 자동화 도구입니다. 훅을 사용하면 일상적인 작업을 수동으로 요청할 필요가 없어지고 코드베이스 전반에 걸쳐 일관성을 보장할 수 있습니다.

에이전트 훅은 **파일 저장, 새 파일 생성, 파일 삭제**와 같은 IDE 내 특정 이벤트에 대해 자동화된 응답을 설정합니다. 일상적인 작업을 수동으로 요청하는 대신, 이러한 이벤트들이 발생할 때마다 미리 정의된 에이전트 작업이 자동으로 실행됩니다.

## 사용 사례
에이전트 훅은 지능적인 자동화를 통해 개발 워크플로우를 혁신합니다. 일관된 코드 품질을 유지하고, 보안 취약점을 방지하며, 수동 작업 부담을 줄이고, 팀 프로세스를 표준화하여 더 빠른 개발 사이클을 만들 수 있습니다.

소규모 프로젝트에서 작업하든 대규모 코드베이스를 관리하든, 에이전트 훅은 일상적인 작업이 자동으로 그리고 일관되게 처리되도록 보장하여 훌륭한 소프트웨어 구축에 집중할 수 있게 해줍니다.

## 에이전트 훅 작동 원리
에이전트 훅 시스템은 간단한 3단계 프로세스를 따릅니다. 

1. 먼저 시스템이 IDE의 특정 이벤트를 모니터링하고
2. 이벤트가 발생하면 미리 정의된 프롬프트가 에이전트에게 전송됩니다. 
3. 마지막으로 에이전트가 프롬프트를 처리하고 요청된 작업을 수행합니다.

이러한 자동화 흐름은 반복적인 작업을 제거하고 코드베이스 전반에 걸쳐 일관성을 보장합니다.

# MCP 연동

## MCP란?

MCP는 Kiro가 외부 서버와 통신하여 전문화된 도구와 정보에 액세스할 수 있게 해주는 프로토콜입니다. 예를 들어, [AWS Documentation MCP 서버](https://awslabs.github.io/mcp/servers/aws-documentation-mcp-server/)는 Kiro 내에서 직접 AWS 문서를 검색하고, 읽고, 추천을 받을 수 있는 도구를 제공해줍니다.

MCP를 통해 전문화된 지식 베이스와 문서에 액세스하고, 외부 서비스 및 API와 통합하며, 도메인별 도구로 Kiro의 기능을 확장하고, 특정 워크플로우를 위한 맞춤형 도구를 생성할 수 있습니다.

## MCP 구성 파일 구조

MCP 구성 파일은 다음과 같은 구조의 JSON 형식을 사용합니다.

```json
{
  "mcpServers": {
    "server-name": {
      "command": "command-to-run-server",
      "args": ["arg1", "arg2"],
      "env": {
        "ENV_VAR1": "value1",
        "ENV_VAR2": "value2"
      },
      "disabled": false,
      "autoApprove": ["tool_name1", "tool_name2"]
    }
  }
}
```

**구성 속성**

| 속성      | 타입    | 필수 | 설명                                     |
| ------------- | ------- | -------- | ----------------------------------------------- |
| `command`     | String  | 예      | MCP 서버를 실행할 명령어               |
| `args`        | Array   | 예      | 명령어에 전달할 인수                |
| `env`         | Object  | 아니오       | 서버 프로세스를 위한 환경 변수    |
| `disabled`    | Boolean | 아니오       | 서버 비활성화 여부 (기본값: false) |
| `autoApprove` | Array   | 아니오       | 프롬프트 없이 자동 승인할 도구 이름    |

## 구성 위치

MCP 서버는 두 가지 수준에서 구성할 수 있습니다.

1. **워크스페이스 수준**: `.kiro/settings/mcp.json`
   - 현재 워크스페이스에만 적용됩니다
   - 프로젝트별 MCP 서버에 이상적입니다
2. **사용자 수준**: `~/.kiro/settings/mcp.json`
   - 모든 워크스페이스에 전역적으로 적용됩니다
   - 자주 사용하는 MCP 서버에 가장 적합합니다

두 파일이 모두 존재하는 경우 워크스페이스 설정이 우선하여 구성이 병합됩니다.

## 구성 파일 생성

**명령 팔레트 사용**

명령 팔레트를 열고 (Mac: `Cmd + Shift + P`, Windows/Linux: `Ctrl + Shift + P`) "MCP"를 검색한 다음 다음 옵션 중 하나를 선택합니다.
   - **Kiro: Open workspace MCP config (JSON)** - 워크스페이스 수준 구성용
   - **Kiro: Open user MCP config (JSON)** - 사용자 수준 구성용

**Kiro 패널 사용**

Kiro 패널을 열고 **Open MCP Config** 아이콘을 선택합니다.

```json
{
  "mcpServers": {
    "web-search": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-bravesearch"
      ],
      "env": {
        "BRAVE_API_KEY": "your-api-key"
      }
    }
  }
}
```

## 환경 변수

많은 MCP 서버는 인증이나 구성을 위해 환경 변수가 필요합니다.

```json
{
  "mcpServers": {
    "server-name": {
      "env": {
        "API_KEY": "your-api-key",
        "DEBUG": "true",
        "TIMEOUT": "30000"
      }
    }
  }
}
```

## 서버 임시 비활성화

구성을 제거하지 않고 MCP 서버를 임시로 비활성화하려면:

```json
{
  "mcpServers": {
    "server-name": {
      "disabled": true
    }
  }
}
```

## 보안 모범 사례

- MCP 서버를 구성할 때는 민감한 토큰이 포함된 구성 파일을 버전 관리 시스템에 커밋하지 않아야 합니다. 
- 가능한 경우 민감 정보에 환경 변수를 사용합니다.
- `autoApprove`에 추가하기 전에 도구 권한을 미리 검토해야 합니다. 
- 프로젝트별 서버에는 워크스페이스 수준 구성을 사용하며, 사용되는 API 키와 토큰은 정기적으로 교체해야 합니다.

## 구성 문제 해결

- MCP 구성이 작동하지 않는 경우 JSON 구문을 검증하여 구문 오류가 없는지 확인하고 누락된 쉼표, 따옴표 또는 대괄호를 확인합니다. 
- 지정된 명령이 PATH에 존재하는지 확인하고 터미널에서 직접 명령을 실행해 봅니다. 
- 필요한 모든 환경 변수가 설정되어 있는지 확인하고 환경 변수 이름의 오타를 확인합니다. 
- MCP 구성 변경 사항을 적용하려면 Kiro를 다시 시작해야 하므로 Kiro를 닫고 다시 열어 변경 사항을 적용합니다.
